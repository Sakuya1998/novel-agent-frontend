# 项目架构规范

## 分层职责

- `src/app/`：路由、页面装配和应用级导航，不承载领域 API 细节。
- `src/pages/`：路由页面容器，负责页面级数据准备和布局组合。
- `src/components/`：可复用界面组件；组件通过 props 接收数据和事件，不直接持有跨页面业务状态。
- `src/features/`：按领域组织的查询、工作流和领域页面适配层。
- `src/api/`：API 客户端、请求错误归一化和生成类型；业务组件不得直接拼接 fetch URL。
- `src/auth/`、`src/permissions/`、`src/workspaces/`：认证、权限和工作区上下文边界。
- `src/*.ts`：仅保留跨领域的基础 Hook、类型或兼容逻辑；新增业务代码优先放入对应领域目录。

## 依赖方向

页面可以组合特性和组件；特性可以调用 API、类型和工具；基础组件不得反向依赖页面。跨领域共享逻辑必须有清晰的输入输出，并配套测试。优先使用 React 状态和现有 Provider，避免新增全局状态库。

## 数据流

页面负责加载状态、空状态和错误状态；Hook 负责请求生命周期和副作用；组件负责展示与用户事件。长任务、轮询和恢复逻辑集中在 jobs 相关 Hook 中，禁止在多个组件复制。
