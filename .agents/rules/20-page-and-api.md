# 页面与接口规范

## 页面与路由

路由定义集中在 `src/app/router.tsx`，路径生成使用同一模块的函数，禁止在组件中硬编码重复路径。页面必须覆盖加载、空数据、错误、只读和权限不足状态；页面容器不直接实现复杂业务流程。

界面组件使用 `PascalCase` 文件名和命名导出。交互文案、按钮状态和错误提示保持清晰一致；新增响应式布局时同时检查桌面 Chromium 和移动 Chromium。

## API

后端契约唯一来源是 `openapi/novel-agent-v1.json`。修改契约后运行 `pnpm run generate:api`，再通过 `src/api/client.ts` 或 `src/api.ts` 暴露领域方法。禁止在页面或组件中直接调用 `fetch`、拼接 API origin 或复制响应类型。

API 方法必须明确输入、成功返回值和错误语义；网络错误、鉴权失败、空响应和长任务状态要转换成 UI 可处理的状态。涉及异步任务时复用既有 job 恢复、事件和取消模式，并测试成功、失败和中断路径。
